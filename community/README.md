# Leo 工作台 · 朋友共创版

个人行动与复盘工作台：每天的重点、按小时对照的计划/实际、项目进展时间线、沉浸式小结和备份。

这是独立的通用源码，不含作者的日记、项目数据、私人站 ID 或登录凭据。首次进入是空记录，有六个可改名的项目位置。每个账号有自己的记录，项目不是群内共享项目。

## 本地运行（开发者）

需要 Node.js 22.13+（验证环境 Node 24）。在本目录执行：

```sh
npm ci
npm run db:local
npm run dev
```

打开终端打印的 `http://127.0.0.1:5173`，本地登录使用模拟账号。数据保存在本目录被 Git 忽略的 `.wrangler/`，不使用作者的线上数据库。不需要 AI API Key。

本地服务只能用于本机测试：不得把开发服务或原始 Worker 端口直接暴露到互联网。生产依赖 Sites 的可信身份注入与访问控制，普通反向代理不能替代它。

## 检查

```sh
npm run typecheck
npm test
npm run build
```

在开发服务器运行时，另一终端执行 `npm run test:accounts`。这个测试固定访问本机 5173，创建 Alice/Bob 模拟身份，检查记录隔离、越权草稿操作、保存冲突、来源校验和备份恢复。测试草稿只留在本地；不能代替线上两个真实账号验收。

`npm run db:local` 通过 Wrangler **仅执行本地迁移**，见 [D1 官方命令说明](https://developers.cloudflare.com/d1/wrangler-commands/)。

自动 CI 尚未启用：当前 GitHub 凭据不含 workflow 权限。上级 `docs/community-checks.example.yml` 是可供维护者以后启用的配置示例，不会自动运行。

## 使用

1. 到「项目」，编辑一个项目的名称、意义和下一步，其他项目可以先留着。
2. 「今天」记下重点、计划和实际，用时可归入项目和投资/消费/负债。
3. 小结可切换「全屏写作」，两种模式共用同一份内容，仍为 2000 字上限。
4. 「更多 → 人生方向」填写称呼及方向。「更多 → 导出与备份」下载 JSON 或 Markdown。
5. 有问题到 GitHub Issues，只发脱敏步骤和截图，不上传日记、备份、密钥或账号邮箱。

## 托管状态与边界

- **朋友版线上站尚未创建，未开放试用。** 当前环境缺少 Sites 派生工具，作者原私人站不作为试用入口。
- 生产部署依赖 Sites + D1；模板 `.openai/hosting.json` 故意没有 `project_id`。由受支持的 Sites 流程生成独立身份，应用 `drizzle/` 迁移，再验证访问权限。
- 网站可按登录账号分开记录，但运营者有后台管理权限，非端到端加密。先使用非敏感内容试用。云端和本机各有留存；导出可用，账号整体删除流程暂未提供。
- 钉钉在 `lib/community-features.ts` 中关闭，客户端不轮询，服务端拒绝连接/同步。未来开通需维护者自己配置 `SITE_ORIGIN`、`DINGTALK_CLIENT_ID`、`DINGTALK_CLIENT_SECRET`（Secret）及可选 `DINGTALK_CORP_ID`，完成组织授权和回调验证，再启用开关并重新发布；不复用作者公司应用。
- AI 草稿和确认写入逻辑保留。接入需本站的 MCP 连接入口和用户账号支持，现阶段不能承诺群友都能连接。可先使用“复制给 AI”，人工回填。没有额外 AI API 调用，但现有 AI 产品与托管仍有各自额度/费用。
- 默认时区为上海，六个项目位置；暂不支持任意新增项目数量、团队共享项目、后台通知。请优先反馈真实使用阻力。
