检查对象：公开仓库当前主分支及其可达历史、公开截图、社区版默认数据、桌面版程序载荷与实际打包的应用内容。私人网站及其数据不参与构建，也没有迁移到社区版。

## 检查结果

- 新用户昵称和人生方向为空；六个项目是“项目 1”至“项目 6”；任务、时间表、进展、回顾初始为空。
- 已检查源码、文档和历史，未发现作者的个人日记、业务项目内容、私人网站地址、表格链接或凭据。截图逐张检查：空界面或明确标注的虚构示例。
- 构建从指定程序入口产生新目录，只纳入界面文件、程序代码、数据库建表语句与许可证。不复制工作目录；不打包 Git 历史、本地数据库、备份、环境配置、缓存、测试数据或源码映射。
- 每个架构包内的应用载荷须解包后检查，再生成 SHA-256 校验文件；校验值只证明下载文件与发布文件一致，不等同于系统签名。
- 桌面版不提供钉钉连接、云端 MCP 访问、自动上传或遥测。用户主动复制到外部 AI 或上传的内容不在本地隐私边界内。

## 已处理的提交身份

发现两次旧提交使用了真实邮箱。经作者明确同意，已重写公开主分支中的这两次提交，作者/提交者均改为 GitHub 隐私邮箱，并修改本地今后的提交配置。源码内容没有因此变化。

重写主分支不等于从互联网抹除旧信息：别人下载的旧副本无法撤回，旧提交 SHA 的缓存/孤立对象也可能仍被 GitHub 保留。如需清理这些旧链接，需要联系 GitHub 支持。旧克隆请重新下载，不要将旧分支重新合并推送。

## 保留的公开署名

“Leo”产品名称、公开 GitHub 用户名/仓库地址、开源许可证中的作者署名继续保留，用于作品归属和反馈；第三方许可证也保留其原作者信息。它们与个人日记、联系方式、业务记录和账号凭据不同。

自动扫描使用通用格式规则，不能证明任意文本绝对不含隐私。发布前仍需人工检查截图、描述和默认状态；每次更新重新检查，不把本次结果当作永久保证。
