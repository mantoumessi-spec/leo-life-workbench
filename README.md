## 为什么做它

最初，我用 Google 表格管理每周、每天的待办。表格直观，也已经形成了使用习惯。但在真实使用中，我不断遇到小阻力：

- 一件事连续做了三个小时，需要在几个小时格里重复填写。
- 写完之后还要记得点保存。
- 看得到做了什么，却不容易看清时间投到了哪个项目。
- 晚上很累，还要自己把零散经历整理成完整记录。

我希望一点点降低这些阻力，同时保留自己已经习惯的“计划与实际并排看”的方式。

## 目前能做什么

| 功能 | 当前行为 |
| --- | --- |
| 每周规划 | 查看 08:00—22:00 的逐小时计划与实际，选择当天多项重点 |
| 连续时段 | 独立合并计划或实际单元格，连续几小时的事只写一次 |
| 时间分类 | 实际内容右侧选择所属项目，以及投资、消费或负债 |
| 自动保存 | 有效输入自动同步；网络失败和冲突会提示，并保留本机待同步内容 |
| 项目接续 | 关注本周重点、当天安排和到期跟进；一次最多展示三项，已有当天记录不重复追问 |
| 进展时间线 | 按日期查看最近三条或全部历史；同一天可新增多笔，也可修改指定记录 |
| 事项收尾 | 已完成与不再做分别处理，保留历史，可重新打开 |
| 回顾 | 汇总项目进展、当天小结和每周记录 |
| AI 草稿 | 通过私人插件读取上下文、整理或修改草稿；确认后写入，支持撤回；项目进展写入同一条时间线 |

“投资、消费、负债”是用户用于复盘的时间分类；休息不会被系统默认标成负债。口述中没说清的时间先保留为待补内容，不补造时间段。

## 希望怎样使用

```mermaid
flowchart LR
    A["口述今天的经历"] --> B["AI 核对已有记录"]
    B --> C["形成待确认草稿"]
    C --> D["查看或修改"]
    D --> C
    D --> E["明确确认"]
    E --> F["写入时间表、小结、项目进展与选定待办"]
    F --> G["回看记录 / 请求撤回"]
```

目前的语音入口是手机键盘语音转文字，AI 整理在现有 ChatGPT 中完成，工作台负责保存草稿、展示对照和记录确认后的变化。网站本身没有另外调用收费 AI API；这不代表所有人使用 ChatGPT、部署或托管都没有成本。

## 我与 AI 各自做什么

我是 Leo。需求来自我的实际使用，我负责表达问题、决定优先级、提出修改意见和验收体验；AI 协助整理需求、编写代码、测试和准备公开文档。

我希望这个项目能持续呈现：一个具体问题怎样被发现、怎样作出产品取舍，以及上线之后哪些地方还需要验证。公开文字经 AI 协助整理，验证状态按实际完成情况记录。
